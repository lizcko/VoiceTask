# VoiceTask

Веб-приложение на React, TypeScript, Vite и CSS. Слева — чат команд, справа — календарь без навигационного меню. Подготовлено для GitHub Pages по пути `/VoiceTask/`.

## Запуск после клонирования

Установите Node.js 22 и Git. В папке проекта выполните:

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173/VoiceTask/. Для остановки сервера нажмите Ctrl+C.

```sh
npm run build
npm run preview
npm test
```

Сборка находится в `dist`, локальный предпросмотр — http://localhost:4173/VoiceTask/.

## Загрузка в GitHub и публикация

Репозиторий должен называться `VoiceTask` с таким регистром: в `vite.config.ts` задано `base: '/VoiceTask/'`. Адрес опубликованного сайта — `https://YOUR_USERNAME.github.io/VoiceTask/`.

### Если репозиторий GitHub пустой

Замените `YOUR_USERNAME` на своё имя пользователя GitHub. Команды выполняются из папки проекта:

```sh
git init -b main
git add .
git status --short
git diff --cached --stat
git commit -m "Prepare VoiceTask for GitHub Pages"
git remote add origin https://github.com/YOUR_USERNAME/VoiceTask.git
git push -u origin main
```

Перед коммитом просмотрите подготовленный список файлов. В него должны входить исходники, `package.json`, `package-lock.json`, настройки TypeScript/Vite, README, тесты, `.gitignore` и `.github/workflows/deploy.yml`. Локальные зависимости, сборка, `.tools` и приватные конфигурации исключены через `.gitignore`. Сам `.gitignore` не проверяет содержимое исходников на секреты; не вставляйте токены и пароли в код.

Если Git попросит имя и email для коммита, настройте их для этого проекта:

```sh
git config user.name "Ваше имя"
git config user.email "Ваш email или GitHub noreply email"
```

После этого повторите коммит и push. Для входа в GitHub используйте Git Credential Manager или SSH; пароль GitHub для HTTPS push не используется.

### Если репозиторий GitHub уже содержит README или другие файлы

Чтобы сохранить существующую историю, клонируйте репозиторий в отдельную папку, например `VoiceTask-publish`, переключитесь в ней на `main`, затем скопируйте туда файлы этого проекта, включая скрытые `.github` и `.gitignore`. Не копируйте `.git`, `node_modules`, `dist`, `.tools`, `.env` и приватные файлы. Если одинаковые файлы уже существуют, объедините их содержимое перед коммитом. Затем выполните в клоне `git add .`, проверьте `git status --short`, сделайте коммит и `git push origin main`. Не используйте force push для замены существующей истории.

### Включение GitHub Pages

1. Откройте репозиторий на GitHub → **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. Откройте **Actions → Deploy VoiceTask to GitHub Pages**. Если первый запуск произошёл до включения Pages и завершился ошибкой, повторите его через **Re-run all jobs** или **Run workflow**, выбрав `main`.
4. Дождитесь успешного выполнения заданий `build` и `deploy`. Ссылка на сайт появится в задании публикации и в **Settings → Pages**.

Workflow запускается при push в `main` и вручную. Он использует Node.js 22, устанавливает зависимости командой `npm ci`, выполняет `npm run build` и публикует только `dist`. Для публикации применяется встроенный `GITHUB_TOKEN`; личный токен или отдельная ветка `gh-pages` не нужны. В бесплатном личном аккаунте GitHub репозиторий для Pages должен быть публичным; доступность Pages для приватного репозитория зависит от тарифа.

Последующие обновления:

```sh
git add .
git diff --cached --stat
git commit -m "Update VoiceTask"
git push origin main
```

Документация: [Vite — GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [GitHub — custom Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Записи localStorage с локального сайта не переносятся автоматически на `github.io`: у опубликованного сайта другое хранилище браузера. Файлы проекта и существующие локальные данные при подготовке публикации не удаляются. Персональные записи не входят в артефакт GitHub Pages.

## Возможности

- Периоды «День», «Неделя», «Месяц», «Год», переходы по датам и кнопка «Сегодня».
- Фильтры типов записей и поиск по названию/описанию. Поиск применяется ко всем записям; календарь показывает совпадения в выбранном периоде.
- Добавление кнопкой «Создать запись», нажатием на часовую ячейку или через чат.
- Просмотр, редактирование и удаление по нажатию на карточку. Пять цветов и произвольный цвет, отметка важности.
- Пересекающиеся события размещаются рядом. В месяце доступен переход к дню для просмотра всех записей.
- Настройки выходных, последние уведомления и локальное имя профиля.
- Записи и настройки сохраняются в localStorage. Первое открытие заполняет текущую неделю примерами. После удаления всех записей календарь остаётся пустым при перезагрузке.
- Интерфейс адаптирован для мобильных экранов: календарь сверху, чат ниже; недельная сетка прокручивается горизонтально.

## Команды чата

```text
задача Подготовить презентацию; сегодня; 14:00
встреча Созвон с командой; завтра; 10:00; 90
задача Отправить отчёт; 2026-10-15; 16:00; 60; важно
помощь
```

Поля разделяются точкой с запятой. Длительность задаётся в минутах, по умолчанию 60, минимум 15. События не могут пересекать полночь. Название не должно содержать точку с запятой. Неподдерживаемые запросы возвращают объяснение ограничений и подсказку.

## Дальнейшее подключение AI и голоса

LLM, авторизация, сервер, синхронизация и распознавание речи не подключены. Микрофон сообщает о недоступности голосового ввода. Обработчик `sendMessage` в `src/App.tsx` и функция `parseCommand` в `src/calendar.ts` — точки для будущего подключения сервисов. Внешние API-ключи следует хранить на сервере, а не в клиентском коде.

Данные хранятся только в браузере текущего origin: смена адреса, порта или очистка данных браузера создаст отдельное хранилище. Журнал уведомлений хранится только в текущей сессии. Часовой пояс записей соответствует локальному времени устройства; подпись GMT в календаре отображает текущий часовой пояс.

Изображение-макет в исходном сообщении было недоступно. Вёрстка следует текстовому описанию; точное визуальное сравнение с оригинальным изображением не выполнялось.
